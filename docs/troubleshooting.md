| Symptom | Cause and fix |
|---|---|
| Swagger UI shows `Failed to load API definition` / `404 /docs/openapi3.yaml` | The documents don't exist yet. IntelliJ runs and `bootRun` generate them automatically before starting (`generateOnRun`). If you started the app another way (IntelliJ's own build, another IDE), run `./gradlew apiDocs`. You don't need to restart a running app |
| Swagger UI Try it out keeps loading (SSE) | Swagger UI cannot display a stream that never ends. If you document it with `performStream`, it is left out of OpenAPI automatically. Subscribe in AsyncAPI Try it out (`/docs/asyncapi.html#try-it-out`) instead |
| `/docs/asyncapi.html` returns 404 | No AsyncAPI file is generated when no WebSocket, STOMP or SSE messages are documented. It appears once you document messages. If you changed the file name (`asyncApi { fileName }`), open that path |
| Startup log shows `API docs not found: no documents in classpath:static/docs ...` (with `language = "ko"`: `API 문서 없음: ...`) | The app resources don't contain the documents yet. Run `./gradlew apiDocs`, or run the app again through Gradle (`bootRun`, IntelliJ's default setting) |
| Labels in the documents are English (`Back to index`, `API list`, `Constraints:`) and you want Korean | The default language of the texts the library writes is English. For Korean, set `kardx { language = "ko" }` ([Documentation language](configuration.md#documentation-language)) |
| Document labels mix English and Korean (for example `메인으로 돌아가기` but `Common error responses` or `Constraints:`) | The language was set only in yml (`kardx.language`), so the texts written by tests follow it and the texts written by the Gradle plugin stay English. The test log shows a WARN starting with `kardx[KDX-005]: the documentation language is 'ko' … but the Gradle plugin uses 'en'`. Set it in the plugin: `kardx { language = "ko" }` ([Documentation language](configuration.md#documentation-language)) |
| A document line is missing from the startup log | The file is missing or has a different name. The Gradle plugin records the actual paths and file names in the app resources (`META-INF/kardx/docs-locations.properties`), so they usually match. If you set `kardx.docs-path` or `startup-log.<document>.file` in the app settings, those values win; remove or fix them ([Startup log](build.md#startup-log)) |
| Warning `kardx[KDX-001]: unknown property 'kardx....'` | A key starting with `kardx.` has a typo and was ignored. Fix it to the key after `Did you mean` in the message. Old flat keys (`open-api-enabled` and so on) should be changed to the key after `It was renamed to` ([yml settings](configuration.md#yml-settings)) |
| Build warning `API docs are packaged into the application ... without sensitive header masking` | The documents are packaged into the executable jar, but some were generated without masking. Turn on `mask-sensitive-headers: true` in the test settings, or turn off `bootJar.enabled` for production builds ([Production exposure](build.md#production-exposure)) |
| Build log `skipped apiDocsIndex — ...` | Only one of index.packageName and baseClass is set, or no test has written a document yet. Set both or remove both ([Index document](asciidoc.md#index-document)) |
| Build error `... spring-restdocs-mockmvc was added without a version, but nothing manages its version` | No BOM manages the REST Docs module the plugin added without a version. Add the `io.spring.dependency-management` plugin or `implementation(platform("org.springframework.boot:spring-boot-dependencies:…"))`, or declare the module yourself with a version ([Dependencies added automatically](build.md#dependencies-added-automatically)) |
| Build warning `com.epages.restdocs-api-spec 0.19.4 does not match Spring Boot 4` | The epages version line doesn't match Boot. Use 0.19.x for Boot 3 and 0.20.x for Boot 4 |
| `The io.github.kardx-project plugin requires Gradle 7.6 or newer` | Upgrade the Gradle wrapper: `./gradlew wrapper --gradle-version <version>` |
| `UnsupportedClassVersionError` (`class file version 61.0`) when Gradle loads the plugin | Gradle runs on a JDK older than 17. Run Gradle on JDK 17 or later: IntelliJ Settings → Build Tools → Gradle → Gradle JVM, or `JAVA_HOME` / `org.gradle.java.home` ([Supported build setups](getting-started.md#supported-build-setups)) |
| `apiDocs` prints `OpenAPI (Swagger) off (apply id("com.epages.restdocs-api-spec") ...)` | The epages plugin isn't applied, so there is no OpenAPI spec, coverage or viewer. Apply it with the version in the message (0.20.x for Boot 4, 0.19.x for Boot 3) |
| `No AsyncAPI spec: kardx.asyncApi.enabled is false. ...` from `apiDocsExport` or `apiDocsUpload` | AsyncAPI generation is off but the export or upload selects it. Turn `asyncApi { enabled }` back on, or set `export { asyncApi = false }` / `upload { asyncApi = false }` ([Exporting specs](outputs.md#exporting-specs)) |
| `apiDocsStubsJar: project.group is not set, ...` | Stub Runner finds stubs by `META-INF/<group>/<name>/<version>`. Set `group = "com.example"` in the build script ([WireMock stub](outputs.md#wiremock-stub)) |
| `apiDocsAggregate: projects : and :root both go to the directory root/ ...` | Two aggregated projects map to the same directory. Aggregate only one of them ([Aggregating multiple projects](outputs.md#aggregating-multiple-projects)) |
| Warning `Source docs: N source files are not UTF-8 (first: ...)` | Some sources aren't UTF-8 (for example `MS949`), so characters in their comments became U+FFFD. Save the sources as UTF-8 |
| `apiDocsCheck` warns `Path variables renamed: /a/{id} → /a/{userId}` | Only the variable name changed; clients call the same URL, so this is a warning, not a removed endpoint. Update the baseline with `apiDocsBaseline` when it's intended |
| `apiDocsCheck` reports the breaking change `Request enum added: ...` | A request parameter or field that accepted any value now has an `enum`, so values clients used to send may be rejected. If intended, update the baseline ([Comparing OpenAPI changes](checks.md#comparing-openapi-changes)) |
| `kardx.startupLogScope: configuration '...' not found. Use developmentOnly or runtimeOnly, or set startupLog = false.` | The configuration named by `startupLogScope` doesn't exist: a typo, or `developmentOnly` in a build where the Spring Boot plugin doesn't create it. Use `runtimeOnly`, or `startupLog = false` ([Startup log](build.md#startup-log)) |
| `Set kardx.restDocsVersion (no Spring Boot plugin to take it from).` | The Asciidoctor plugin is applied without the Spring Boot plugin (a library module, a separate docs project), so the plugin can't pick the `spring-restdocs-asciidoctor` version. Set `kardx { restDocsVersion = "..." }` to your Spring REST Docs version ([Gradle plugin](build.md#gradle-plugin)) |
| `kardx.response-wrapper.data-path needs response-wrapper.class` | The yml sets the data path without the wrapper class. Add `kardx.response-wrapper.class` ([Common response wrapper](http-api.md#common-response-wrapper)) |
| `A header in kardx.upload.headers has no value, for example an environment variable or Gradle property it reads is not set.` | Typically the CI secret isn't passed to the job. Set the environment variable or Gradle property the header reads ([Exporting specs](outputs.md#exporting-specs)) |
| `kardx.bootJar.path must be a directory inside the app's resources such as 'static/docs' or 'public/api-docs', got '...'` | `bootJar.path` is empty, absolute, has a drive letter or uses `..`. Use a relative sub directory of the app resources such as `static/docs` ([Docs in the app resources](build.md#docs-in-the-app-resources)) |
| `kardx.bootJar.path '...' is an application resource root (static, public, resources, META-INF/resources). ...` | The docs would mix with the app's own files in that root. Use a sub directory such as `static/docs` ([Docs in the app resources](build.md#docs-in-the-app-resources)) |
| `kardx.<directory> must not be the project directory, the build directory or one of their parents, because the plugin deletes it before writing: ...` | `snippetsDirectory`, `asciidocDirectory`, `outputDirectory` or `aggregate.outputDirectory` points at a directory the plugin must never empty. Point it at a sub directory, ideally under `build/` ([Directories the plugin empties](build.md#directories-the-plugin-empties)) |
| `kardx.<directory> must not be inside or contain the source directory ..., because the plugin deletes it before writing: ...` | The directory is inside `src/` or the AsciiDoc source directory, or contains one of them. Use a directory under `build/` ([Directories the plugin empties](build.md#directories-the-plugin-empties)) |
| `kardx.<directory> points to ..., which is outside the build directory and holds files the plugin did not write. ...` | Outside `build/`, the plugin only replaces an empty directory or one with the marker file `.kardx-output`. Use a directory under `build/`, empty it, or create an empty `.kardx-output` in it if its contents may be deleted ([Directories the plugin empties](build.md#directories-the-plugin-empties)) |
| Gradle reports that a task uses `build/api-spec/openapi3.yaml` (the output of `openapi3`) without declaring a dependency | The plugin declares the spec files as outputs of `openapi3`, so Gradle 8 and later check readers. Add `dependsOn("openapi3")` to your task ([Gradle plugin](build.md#gradle-plugin)) |
| `Cannot resolve configuration property 'kardx...'` in yml | The IDE hasn't read the configuration metadata in the library jar yet. Sync Gradle again (Reload All Gradle Projects) and it goes away. IntelliJ doesn't read metadata from RUNTIME-scoped dependencies (`developmentOnly`), so the plugin also adds the startup log module to `compileOnly`. If you declared the module yourself, also add `compileOnly(...) { isTransitive = false }` ([Startup log](build.md#startup-log)) |
| `Unresolved reference 'Description'` in production code | The Gradle plugin adds annotations to `compileOnly`. With `addDependencies = false` or without the plugin, add it to `compileOnly` yourself |
| `DocumentationMismatchException: Documented response fields do not match ...` | The documented fields or parameters differ from the actual ones. Check the list, the DSL lines to paste and the hints in the message. The original REST Docs message is in `Caused by` ([Verification failure messages](http-api.md#verification-failure-messages)) |
| `DocumentationMismatchException: ... Type mismatch: - price: documented Number, actual String` | The documented field type differs from the actual JSON type (REST Docs' `FieldTypesDoNotMatchException` is in `Caused by`). Fix the type with the DSL line in the message, or remove the cause. If numbers are strings, look for `@JsonFormat(shape = JsonFormat.Shape.STRING)`, `ToStringSerializer` or `JsonWriteFeature.WRITE_NUMBERS_AS_STRINGS`; if a date documented as a string is a number or array, turn off `WRITE_DATES_AS_TIMESTAMPS`. If the actual value is `Null`, make the property nullable or use `isOptional true` (`optionalAt("...")` for extracted lists); if array elements have different types (`Varies`), document them as `VARIES` ([Verification failure messages](http-api.md#verification-failure-messages)) |
| You want to see what table an extraction result produces without running a test | `println(responseFieldsOf<T>().describe())` ([Previewing extraction results](http-api.md#previewing-extraction-results)) |
| A KDoc or Javadoc comment isn't picked up as a description | Check in this order: (1) the feature is on: it is experimental and off by default, so set `kardx { sourceDocs { enabled = true } }` in the Gradle plugin; the per-item switch for that kind of comment is on (`fieldDocs`, `enumDocs`, `schemaDescriptions`, `paramDocs`, all `true` by default, `methodDocs` `false` by default); and yml `kardx.source-docs.enabled` (default `true`) is not `false`; (2) the class is in a `main` source set of this project or of a `project(...)` dependency (with `sourceDocs { includeProjectDependencies = true }`, the default), not in test sources; (3) the DTO doesn't come from a jar, which has no sources to read (use `@Description` or `description-annotations`); (4) the field has no `@Description` or listed annotation, which wins over the comment; (5) the declaration is one the scanner doesn't collect or uses syntax the lightweight scanner skips ([Known limitations](http-api.md#known-limitations)). Skipped declarations are not logged one by one (`--debug` only shows a file whose reading stopped with an error), so open `build/kardx/source-docs/source-docs.json` and look for the class (JVM binary name, `Outer$Inner`) and the property. Controller comments are used only with `methodDocs = true` and need a known handler, so RestTestClient and functional routes get none ([Descriptions from KDoc/Javadoc](http-api.md#descriptions-from-kdocjavadoc)) |
| `kardx[KDX-101]: path parameter 'id' declared by name only (or with FromParamTag), but no description was found.` | The test declares `pathParameters("id")` (or `FromParamTag`) and no `@param id` was found. Add `@param id` to the KDoc/Javadoc of the handler method and turn on the experimental source docs (`kardx { sourceDocs { enabled = true } }`, with `paramDocs` left at `true`), or describe it in the test (`"id" pathMeans "..."`). The `@param` lookup needs the Gradle plugin (`apiDocsSourceDocs`) and a known handler: RestTestClient, functional routes and `bindToServer` never know it ([Parameters declared by name → method `@param`](http-api.md#parameters-declared-by-name--method-param)) |
| Warning `kardx[KDX-501]: A and B both write X.adoc and share snippet directory 'x'. Rename one of them.` | Two test classes in different packages have the same simple name, so their documents overwrite each other. Rename one class ([Automatic document generation](asciidoc.md#automatic-document-generation)) |
| In parallel tests, one class's documents are built with another class's settings (yml or `configure` wrappers, masking, `document.commonIncludeFiles`, and so on) | Settings are a single JVM-wide value. Each test removes only the `configure` it added, so tests don't erase each other's settings, but while they run at the same time, blocks added by other tests and yml values from other contexts (profiles, `@TestPropertySource`) apply together. Give per-test values with `withSettings`, or run those classes one after another (`@Execution(ExecutionMode.SAME_THREAD)`, `@ResourceLock`). If you run methods of the same class in parallel, the settings of the last test that writes the document are also undefined ([Parallel execution](configuration.md#parallel-execution)) |
| A value set with `configure` remains after the test ends | It was called somewhere other than the test thread (threads or thread pools the test created, `@BeforeAll`, the body or `beforeSpec` of a Kotest spec in isolation mode). Call it on the test thread (`@BeforeEach` or the test body, Kotest `beforeEach`) or `reset()` in `@AfterAll` ([Configuration](configuration.md#how-to-change-settings), [Kotest](kotest.md#same-behavior-as-the-junit-extension)) |
| The section order in the generated document is not what you want | The default is method name order. Use `@TestMethodOrder(MethodOrderer.OrderAnnotation::class)` + `@Order` ([Section order](asciidoc.md#section-order)) |
| The result of `mockMvc.get("/x") { }` or of `MockMvcTester` has no `andDocument` | Import `io.github.kardx.mockmvc.andDocument`; that one import covers `ResultActions`, `ResultActionsDsl` and `MvcTestResult`. If the IDE imported another `andDocument` (for example the WebTestClient one), replace that import |
| `Fields with the following paths were not found in the payload: [items[].x]` | The array in the test response is empty. Add data, or make the element fields optional: `responseFields(responseFieldsOf<T>().optionalUnder("items[]"))`. To apply this to every array, use `array-element-fields-optional: true` (for a single test, `withSettings({ extraction.arrayElementFieldsOptional = true })`) |
| `The following parts of the payload were not documented` | The extracted type differs from the actual response. The extractor can't know about settings that change the shape, such as `@JsonInclude` or custom serializers, so describe those fields by hand or relax that section: `relaxed(RelaxedSection.RESPONSE_FIELDS)` ([Relaxed verification](http-api.md#relaxed-verification)) |
| Field names differ from the response (`userName` vs `user_name`) | `restDocsMockMvc` follows the naming strategy of the app's mapper. If you built the mapper yourself, align the `objectMapper` setting with the app |
| WebFlux app tests fail with `No bean named 'webHandler' available` | Spring MVC is on the test classpath, so the app started as a servlet app. The Gradle plugin automatically excludes epages' `spring-boot-starter-web` (Boot 3 and 4) for projects that declare `spring-boot-starter-webflux` (`excludeServletStarterForWebFlux`). Without the plugin, `exclude` it yourself. The core library doesn't pull in MockMvc ([WebTestClient dependencies](webtestclient.md#dependencies)) |
| In a WebFlux app, `/docs/openapi3.yaml` downloads instead of opening (`application/octet-stream`) | WebFlux (Netty) doesn't know the `.yaml` media type, and `server.mime-mappings` is servlet-only. Use a `WebFluxConfigurer` to give the `/docs/**` resource handler `setMediaTypes(mapOf("yaml" to MediaType("text", "yaml", Charsets.UTF_8)))` ([When the docs YAML downloads instead of opening](webtestclient.md#when-the-docs-yaml-downloads-instead-of-opening-webflux)) |
| WebTestClient `andDocument` fails with `REST Docs configuration not found` | The client has no REST Docs filter. Create it with `restDocsWebTestClient(context, provider)` or add `.restDocs(provider)` to the builder |
| `api-summary` in WebTestClient documents shows the actual path (`/api/users/1`), and epages throws `MissingUrlTemplateException` | Requests built with the `uri { ... }` builder have no URL template. Use a template, as in `uri("/api/users/{id}", 1)` |
| On Boot 4, value class fields are serialized as `id-QXt-Mfc` | You need `tools.jackson.module:jackson-module-kotlin` for Jackson 3 |
| `include::_landing.adoc[]` error | The file in `document.commonIncludeFiles` is not in `src/docs/asciidoc` |
| Tokens and session values appear as is in the documents | Masking is off by default. Turn it on with `mask-sensitive-headers: true` or `masking.maskSensitive()`. It also masks well-known credential query and form parameters (`access_token`, `password`, `client_secret` … in the URI query or an `application/x-www-form-urlencoded` body); add others with `masked-query-parameters` ([Masking sensitive data](configuration.md#masking-sensitive-data)) |
| `StompTestClient` fails with `STOMP ERROR from server: <message>: <body>` | The server answered with a STOMP `ERROR` frame (a channel interceptor rejected the CONNECT, SEND or SUBSCRIBE, an unknown destination …). The text after the prefix is the server's `message` header and body; fix the cause on the server side or in the test (missing token, wrong destination). `STOMP connection failed: ...` means the connection dropped ([StompTestClient](messaging.md#sending-and-receiving-with-stomptestclient)) |
| The `Date` response header is missing from the documents | It is removed by default so snippets stay identical between runs. Keep it with `http.removedResponseHeaders = emptySet()` (`removed-response-headers: none`) or document it with `responseHeaders(...)` (the DSL, or REST Docs' `responseHeaders` passed to `snippets(...)`). A yml `removed-response-headers` list replaces the default, so `Date` comes back unless you list it too ([Reproducible snippets](build.md#reproducible-snippets)) |
| `Set-Cookie` in the documents has no `Expires` attribute | `Expires` is dropped when the cookie also has `Max-Age`, because it is computed from the current time and would change every snippet on every run; `Max-Age` has the same meaning. Set `http.removedResponseHeaders = emptySet()` (`removed-response-headers: none`) to keep the header as received |
| Every description is `No description` | `@Description` is missing, another annotation (`@Schema` and so on) is not listed in `description-annotations`, or a custom `descriptions.resolver` looks at a different annotation and doesn't fall back to the default steps (end it with `orElse DescriptionResolver.DEFAULT`). Annotations written in Java must have `@Retention(RUNTIME)` ([Reading descriptions from other annotations](http-api.md#reading-descriptions-from-other-annotations)) |
| `kardx.description-annotations: class '...' not found` | The class name has a typo, or the annotation's dependency is missing. Aliases (`swagger`, `jackson`) also need the dependency ([Errors and fixes](http-api.md#errors-and-fixes)) |
| Constraints are missing from the documents | Check that `jakarta.validation-api` is on the classpath and that your custom template didn't remove the Constraints column |
| `AbstractMethodError` in Asciidoctor (Boot 4) | You need AsciidoctorJ 3. The Gradle plugin sets it automatically; if you configured it yourself, add `asciidoctorj { setVersion("3.0.1") }` |
| An API that requires authentication is documented as 200 without authentication, or the warning `kardx[KDX-006]: the application context has a springSecurityFilterChain bean, but restDocsMockMvc does not apply it` | `restDocsMockMvc` doesn't apply the Spring Security filter chain by default. If the API is protected by Spring Security, turn it on with `kardx.apply-spring-security: true`, add `spring-security-test`, and authenticate with `with(jwt())` or `with(user(...))`. If documenting without the filter chain is intended, set `apply-spring-security: false` explicitly and the warning goes away. This setting is read when the MockMvc is created, so set it before calling `restDocsMockMvc` ([Spring Security](http-api.md#spring-security)) |
| An API authenticated with `with(jwt())` or `@WithMockUser` has no Swagger Authorize | The request has no `Authorization` header, so no security scheme was created. Declare one with `openApi { bearerAuth() }` (`basicAuth()` for Basic) ([Security schemes for tests that authenticate without a header](http-api.md#security-schemes-for-tests-that-authenticate-without-a-header)) |
| The response body in the documents is `<binary: 1234 bytes>` | For bodies that aren't text (PDF, images, `application/octet-stream` …), only the size is kept. This is intended; the `Response File` table next to it shows the media type, file name, and size, and `responseFile("...")` adds a description. If a text body shows up like this, check the response `Content-Type` ([File downloads](http-api.md#file-downloads)) |
| Build log `OpenAPI schema names: Item → OrderItem (...)` | The Gradle plugin split schemas that have the same name but different structures. If you want a specific name, use `openApi { responseSchema = "..." }` ([Schema names](http-api.md#schema-names)) |
| Build warning `OpenAPI schema names: ...: set VARIES where the same path has different types ...` | You used the same explicitly chosen schema name for responses with different structures. Give each test a different name |
| Log `kardx[KDX-107]: responseFieldsOf<...>() found nothing to document` | The type has no fixed fields to document (a single-value body, a `Map` without a path). Give a path or remove that entry ([Empty extraction results](http-api.md#empty-extraction-results)) |
| `Query parameters with the following names were not documented: [...]` even though you passed `parametersOf<T>()` | The extraction result is empty or the names differ. `Pageable` and `Sort` are extracted as `page`, `size` and `sort`, so if you renamed them, describe them by hand ([Spring Data pages](http-api.md#spring-data-pages)) |
| Field verification fails with `@JsonView`, `@JsonFormat(shape = OBJECT)`, `@JsonAlias` and similar | These are serialization features the extractor can't follow ([Unsupported shapes](http-api.md#unsupported-shapes)) |
| Every Java record field is Required `false` | Java reference types without annotations are treated as optional. If a field is required, add `@NonNull` or `@NotNull`, or put `@NullMarked` on the package ([Extraction rules](http-api.md#extraction-rules)) |
| Kotest: `IllegalStateException: kardx[KDX-401]: no Kotest leaf test is running` | You documented a request outside a leaf test (`then`, `it`, `test`), that is, in the spec body or a `given` or `describe` block, or you didn't register `RestDocsExtension`. Move the request and `andDocument` into a leaf test, and register the extension in the spec (`extension(RestDocsExtension())`) or in the project config ([Kotest](kotest.md#registration)) |
| Kotest: `kardx-kotest is built for Kotest 6.x, but Kotest 5.x is on the test classpath` (or the reverse) | The Kotest version and the artifact don't match. Use `kardx-kotest5` for Kotest 5.x and `kardx-kotest` for 6.x. The Gradle plugin picks the right one based on the declared Kotest version ([Dependencies by Kotest version](kotest.md#dependencies-by-kotest-version)) |
| Gradle: `Cannot select module with conflict on capability 'io.github.kardx-project:kardx-kotest-extension'` | Both `-kotest` and `-kotest5` are on the classpath. Keep only one (`exclude` it if another dependency pulls it in) |
| Kotest 5.x: snippets are generated but the spec document (`.adoc`) is missing | The spec's `override fun extensions() = listOf(RestDocsExtension())` creates a new instance on every call. Keep the instance in a property and return it ([Kotest 5.x](kotest.md#kotest-5x)) |
| Kotest: warning `tests '...' and '...' in ... map to the same snippet directory` | Two test names in the same spec become identical after normalization (`get (a)` and `get [a]`). The later one gets `-2`, but that can change with execution order, so rename the tests ([Snippet directory name](kotest.md#snippet-directory-name)) |
| Method names in clients generated by OpenAPI Generator and similar tools are empty or collide (Korean test names) | You chose the `test-name` rule, or the handler of the request is unknown (functional routers, WebTestClient without handler recording), so the operationId is the test name (`<spec>.<snippet directory name>`) and contains Korean. Code generators strip non-ASCII characters. Fix: (a) `openApi { operationId = "..." }` on that test, or (b) switch the rule to `handler-method` (default) or `path` ([operationId](http-api.md#operationid)) |
| Build log shows `OpenAPI operationId: '...' is set on several operations` | The same id set with `openApi { operationId }` or `openApi.operationIdResolver` is on several operations. Explicitly set ids are not changed, so give each test a different id |
| After running a single Kotest test, the `-2` in a snippet directory name disappeared | The number added to tests that end up with the same name follows execution order. Rename the tests so they don't collide ([Snippet directory name](kotest.md#snippet-directory-name)) |
| Kotest: `currentTestProvider` on a new thread fails with `no Kotest leaf test is running` | Threads outside coroutines can't find the current test. Move the work into a coroutine (`withContext(Dispatchers.IO)`) or use the `provider` of the extension registered in the spec (it falls back to the most recently started test) |
| In Kotest isolation modes, `include::...[]` or settings are applied several times | Isolation modes run the spec body and `beforeSpec` again for each instance, so `configure` calls pile up. Configure in `beforeEach` ([Kotest](kotest.md#same-behavior-as-the-junit-extension)) |
| A Kotest spec's document is missing from the index | No test in it was documented, or all of them failed. If you set `index.packageName`, the spec may be outside that package (including subpackages). If you remove the setting, every spec that produced a document is included ([Index and OpenAPI](kotest.md#index-and-openapi)) |
| `kardx.*` in yml isn't applied to Kotest specs | The Kotest Spring extension (6.x `io.kotest:kotest-extensions-spring`, 5.x `io.kotest.extensions:kotest-extensions-spring`) isn't applied to the spec. For 6.x, register it with `@ApplyExtension(SpringExtension::class)` or in the project config; for 5.x, in the project config or the spec's `override fun extensions()` ([Using with Spring](kotest.md#using-with-spring)) |
| `*` or backticks in `@DisplayName` render as bold or code | They are interpreted as AsciiDoc formatting. Escape them as `\*` or wrap the text in `+...+` ([Snippets and sections by test shape](asciidoc.md#snippets-and-sections-by-test-shape)) |
| Path variables or parameters appear as `type: string` in OpenAPI, and a numeric default value is `"20"` | The type of a hand-written parameter comes from the controller parameter, but the handler of this request is unknown: a WebTestClient without `recordHandlers()` (`bindToController`, `bindToRouterFunction`), functional routes, or `bindToServer`. Use a client that records handlers (`restDocsWebTestClient`, `recordHandlers()`) or add `ofType Long::class`. It's also `string` when the controller parameter is a `String` or has a different name (Java compiled without `-parameters`) ([Parameter types come from the handler](http-api.md#parameter-types-come-from-the-handler)) |
| Warning `kardx[KDX-204]: GET /... in ... does not document path variable(s) id` | A path variable of the URL template isn't documented in the block, so it appears in OpenAPI without a description. Paste the `pathParameters(...)` line at the end of the message into the `andDocument` block. The warning appears once per test ([Parameter types come from the handler](http-api.md#parameter-types-come-from-the-handler)) |
| In Swagger UI, APIs pile up in the `default` group / `summary` is empty | Operations documented with this library's `andDocument` always get a tag (the document class title) and a summary (the test display name). If they are empty, the operation was documented outside this library (a test that calls epages `MockMvcRestDocumentationWrapper.document` or `resource(...)` directly). Move it to `andDocument` ([OpenAPI tags and summaries](http-api.md#openapi-tags-and-summaries)) |
| The summary of an operation documented by several tests is one test's name (`Pay by bank transfer`), or the build warns `OpenAPI summary/description: ... tests declare different summary values` | The merged operation takes the representative test's name. Set the operation name with `openApi { summary = "..." }`, using the same value in every test of that operation; with different values the first in snippet directory order wins ([OpenAPI tags and summaries](http-api.md#openapi-tags-and-summaries)) |
| `apiDocsCheck` fails with `No OpenAPI baseline: ...` | Without a baseline file it fails unless `failOn = "none"`. Create one with `./gradlew apiDocsBaseline` and commit it, or to let it pass as before, set `openApiCheck { requireBaseline = false }` ([Comparing OpenAPI changes](checks.md#comparing-openapi-changes)) |
| `kardx { upload { timeout = java.time.Duration.ofSeconds(30) } }` fails with `Unresolved reference: time` | Inside the block, `java` resolves to the Java plugin extension. Put `import java.time.Duration` at the top of the build script and write `Duration.ofSeconds(30)` ([Exporting specs](outputs.md#exporting-specs)) |
| OpenAPI lacks `minLength`, `format`, `multipart/form-data` or `in: cookie` | The Gradle plugin (`io.github.kardx-project`) adds them after `openapi3`. With only the epages plugin, only part of them are emitted ([Without the Gradle plugin](http-api.md#without-the-gradle-plugin)) |
| A hand-written `type ENUM ... enumOf X::class` fails with `Type mismatch: - status: documented String, actual Number` | The enum's `@JsonValue` is a number. Enum field types are verified against the actual JSON type. Use `type NUMBER` (extracted fields are matched automatically) |
| Redocly `no-invalid-media-type-examples` warning | An example violates the schema. If it is the request example of a test that documents a validation failure (an empty name, a negative price), this is intended. For a success test, check the constraints or the example data |
| `errorResponse status must be between 400 and 599, but was 302` | `errorResponse(...)` declares error responses only. Document redirects and other statuses with a test ([Declared error responses](http-api.md#declared-error-responses)) |
| `errorResponse(409) is declared more than once in this andDocument block` (or `needs a non-blank description`, `has a blank contentType`, `has a blank example`) | One declaration per status in a block, each with a description. To leave out the example, remove `example(...)` instead of passing an empty one |
| `responseFile cannot be used together with responseFields` (or `requestFile cannot be used together with requestFields`, `... with requestParts`) | A file body has no fields. Remove `responseFields` from a download test, and describe multipart file parts with `requestParts` instead of `requestFile` ([File downloads](http-api.md#file-downloads)) |
| `DocumentationMismatchException: Documented errorResponse(409) fields do not match the actual example.` | The declared example has a field that `fields(...)` doesn't list, or lacks a required one. Fix the example or the fields. This is the only check on declared responses ([Declared error responses](http-api.md#declared-error-responses)) |
| `the example of errorResponse(409) is not valid JSON for content type application/json` | The example text isn't JSON. Fix it, pass an object to `example(...)`, or set a non-JSON `contentType` |
| A declared error response is missing from the document and OpenAPI | The test itself received that status. The real response documents it, so the declaration is dropped without a warning |
| `errorResponse(409, "...", example)` produces an example but no field table | The example is a collection, array, `Map`, generic class or plain value, so fields can't be extracted from its runtime class. Use the block form: `errorResponse(409, "...") { fields<RestResponse<ErrorBody>>(); example(example) }` |
| A modifier has no effect: after `AUTH isOptional true` on its own line, `requestHeaders(AUTH)` is still required | Modifiers return a copy and leave the original unchanged. Use the result: `requestHeaders(AUTH isOptional true)` ([Entry syntax](http-api.md#entry-syntax)) |
| Undocumented query parameters, cookies or links don't fail a test with `relaxed = true` | `relaxed = true` relaxes every section. To relax only the body, use `relaxed(RelaxedSection.REQUEST_FIELDS, RelaxedSection.RESPONSE_FIELDS)` ([Relaxed verification](http-api.md#relaxed-verification)) |
| RestTestClient `andDocument` fails with `this RestTestClient has no REST Docs configuration. Build it with restDocs(provider).` | Add `.restDocs(provider)` to the builder before `build()` ([RestTestClient](webtestclient.md#resttestclient)) |
| `Could not connect to STOMP endpoint ws://localhost:.../ws` | The app isn't listening there (use `@SpringBootTest(webEnvironment = RANDOM_PORT)` and `@LocalServerPort`), the path is wrong, or the server refused the CONNECT frame (missing or invalid `connectHeaders`) ([StompTestClient](messaging.md#sending-and-receiving-with-stomptestclient)) |
| `No STOMP frame arrived on /topic/... within PT5S after sending to /app/...` (`sendAndReceive`), or `No STOMP frame arrived on /topic/... within PT5S.` (`StompSubscription.await`) | Nothing was published to the subscribed destination. Check that `subscribeTo` matches where the server sends (`/topic/rooms.1`, not the template `/topic/rooms.{roomId}`), or pass a longer `timeout` |
| `No RestDocumentationContext. Call MessageDocumentation inside a test method run by AutoRestDocumentationExtension (or RestDocumentationExtension).` | `MessageDocumentation` was used outside a documented test: in `@BeforeAll`, on another thread, or in a class without the extension. In Kotest, pass `restDocs.provider` or `RestDocsExtension.currentTestProvider` ([WebSocket / STOMP](messaging.md#websocket--stomp)) |
| ``Expected 3 stream events within PT5S but received 1. Increase `timeout`, or trigger the events in `whileStreaming`.`` | `performStream` waited for `eventCount` events and fewer arrived. Trigger the events inside `whileStreaming`, lower `eventCount`, or pass a longer `timeout` ([Streams that never end](messaging.md#streams-that-never-end)) |
| `--security expects name=bearer\|basic\|apiKey:<header\|query\|cookie>:<name>, got ...`, or `kardx.asyncApi.apiKeyHeader needs an HTTP header name` | The scheme value is malformed. Use `bearer`, `basic` or `apiKey:<header\|query\|cookie>:<name>` ([Authentication in AsyncAPI](messaging.md#authentication-in-asyncapi)) |
| AsyncAPI Try it out: plain WebSocket or SSE connection is rejected although a token is entered | Browsers can't set headers on the WebSocket handshake or on `EventSource`, so header credentials are sent only over STOMP. | `apiDocsCoverage` reports an endpoint as undocumented although a test documents it | Coverage counts an endpoint as documented when an OpenAPI fragment (`resource.json`) has the same method and path template. Tests left out of OpenAPI (`openApi { excluded = true }`, `openApi.enabled = false`) count too, by their actual request path. Check that the request was built from a template (`get("/api/users/{id}", 1)`, not the WebTestClient `uri { }` builder, which records the actual path), that the method matches, and, with API versions, that the documented version is the endpoint's version ([Documentation coverage](checks.md#documentation-coverage)) |
| An endpoint you know is undocumented doesn't appear in the coverage report, or `apiDocsCoverage` prints `no endpoint inventory` | The inventory holds only what the test application contexts contain. Standalone setups (`standaloneSetup`, `bindToController`, `bindToRouterFunction`) have no context to read, functional routes (`RouterFunction`, `router { }`) aren't read, and slice tests (`@WebMvcTest(UserController::class)`) list only their controllers. Add one `@SpringBootTest` documentation test so every controller is listed ([Endpoints that aren't in the inventory](checks.md#endpoints-that-arent-in-the-inventory)) |
| Build warning that an operation uses `oauth2` or `openIdConnect` but `openApiSecurity` doesn't configure it, and Swagger UI shows no OAuth2 login | A test declared `openApi { oauth2(...) }` or `openIdConnect(...)`, but the build has no flows or discovery URL for it, so the security requirement can't be written. Add `kardx { openApiSecurity { oauth2 { ... } } }` ([OAuth2 and OpenID Connect](http-api.md#oauth2-and-openid-connect)) |
| Build warning about API versions left out of the spec, and Swagger UI shows only the newest version of an endpoint | The same path and method are documented in several versions, and one spec keeps only the highest. | A Kotlin default value (`val size: Int = 20`) doesn't appear as `default` | Defaults are read only when extracting requests (`parametersOf<T>()`, `requestFields<T>()`), not `responseFields<T>()`. Only strings, numbers, booleans and enums are read, and only when the library can create an instance from the defaults. Otherwise add `withDefaultValue "20"` to the entry ([Defaults, examples, and constraint notes](http-api.md#defaults-examples-and-constraint-notes)) |
| `ParameterResolutionException: Discovered multiple competing ParameterResolvers` for a `MockMvc` or `WebTestClient` test method parameter | Another JUnit extension of yours also resolves that type, and `AutoRestDocumentationExtension` now fills these parameters too. ## Error codes

Library errors and warnings start with `kardx[KDX-xxx]` and end with a link to the row below. The code stays
the same when the wording changes, so search for the code. The hundreds digit is the stage: `0xx` test setup and
settings, `1xx` documenting, `2xx` OpenAPI, `3xx` messages (WebSocket, STOMP, SSE), `4xx` Kotest, `5xx` files, `6xx`
startup log. Rows marked (warning) don't fail the test.
